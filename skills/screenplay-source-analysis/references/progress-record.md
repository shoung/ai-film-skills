# 章級進度、覆蓋與 QA 紀錄

## 1. 章級進度與續跑

逐章分析用 `ch-<sequence>-extract.md` 命名，補零與否沿用同一專案的做法。分析目錄放同批章檔，進度表、彙總和審查檔另存。

每份章分析檔第一行放來源標記。填入索引 `source.sha256` 的 64 位小寫十六進位值。

```markdown
<!-- source_sha256: <source.sha256> -->
```

進度表記錄原著與索引檔路徑、來源 SHA-256、`verify` 結果及目標章序。索引章序（`sequence`）在下表連續，原文章號（`source_number`）保留原書標示。

| 索引章序 | 原文章號與標題 | 原文起訖行 | 分析檔 | 進度 | 警示 |
|---|---|---|---|---|---|
| 1 | 第一章 少年出谷 | 1–120 | `ch-0001-extract.md` | 完成 | |
| 2 | 第三章 退婚風波 | 121–245 | `ch-0002-extract.md` | 完成 | 原文章號由 1 跳到 3 |
| 3 | 第三章 宗門秘藏 | 246–380 | `ch-0003-extract.md` | 進行中 | 原文章號 3 重複 |

續跑先對原文執行 `verify`，再用含 `--require-source-hash` 的 `coverage` 盤點待補章檔。原文或章界改變後，保留舊批次的章檔及 QA，另開批次重新分析和審核。來源標記只記錄所用版本，分析內容應與該版本重新核對。

## 2. 索引與覆蓋異常

`verify` 通過後，原書跳號、重號及章段 `char_count < 50` 可記為警示並繼續。索引無效、章序不連續或來源雜湊不符時，須先修正索引並重驗。

`coverage --start/--end` 限定預期章序，檔名及來源標記仍會檢查同目錄的分析檔。依下列欄位修正，直到 `complete: true`，再整理該範圍的彙總。核對時保留 `unexpected` 的結果，因它單獨有值時仍可能回報 `complete: true`。

| 欄位 | 處理 |
|---|---|
| `missing` | 補齊指定範圍缺少的章檔。 |
| `unmatched_files` | 核對命名，將彙總、進度等非章檔放到章分析目錄外。 |
| `unverified_files` | 檢查索引和章檔的來源標記，從原文核對後補齊。 |
| `stale_files` | 檔內雜湊與索引不同。保留舊成果，在本批次對新來源重新分析。 |
| `unexpected` | 確認超出索引的章檔是否誤放。 |

覆蓋檢查的範圍是章檔、檔名及標記。證據是否吻合原文，由獨立 QA 檢查。

## 3. 彙總標頭

在全域彙總開頭記錄分析模式、起訖索引章序、實際分析章數及跳過的索引章序。原文章號的異常另列。

```markdown
# 全域情節與改編候選彙總報告

- 分析模式：指定範圍
- 索引章序範圍：1–50
- 實際分析：50 章
- 跳過的索引章序：無
- 原文章號警示：原書從第 3 章跳至第 5 章
```

## 4. 獨立 QA 狀態管制與檢核表

由未參與分析的審核者抽核成果並記錄判定，創作者也可擔任。無獨立抽查證據時標為「待審」。證據及交付檢核均符合要求時標為「通過」。發現引用、來源、覆蓋或未經裁決的改編定案等問題時標為「退回」，附具體章檔與缺陷。

```markdown
# 獨立品質審核檢核表

- 檢核對象及範圍：
- 審核人及時間：
- 判定：待審／通過／退回

| 檢核項目 | 結果 | 抽查證據或問題 |
|---|---|---|
| 原文唯讀性及來源版本 | | 原文保留，索引 SHA-256 與 verify 結果 |
| 章級覆蓋 | | strict coverage 結果與任何額外章檔 |
| 引文與行號 | | 隨機抽查 5 處，逐一核對精確行號且只摘必要詞句。引文不足 5 處時全查。 |
| 原文未交代事項 | | 已標記 `【原文未明確】` 並列入未決問題 |
| 改編候選與範圍 | | 候選交創作者裁決，彙總標頭列明範圍與跳過章序 |
```
