# 視頻提示詞生成工作流 V2.0（執行主文件）

skill 作者（抖音/B站）：Elio_AIGC

> 執行定位：基於劇本與視覺資產，生成以 Seedance 為主的高效視頻提示詞。
> 結構範例請統一參閱同目錄 `format-example.md`（提示詞密度與主示範之單一來源）。

## 1. 核心生成與請求原則

1. **獨立控制單元與分組決策**：每個請求為獨立生成單元，可包含單鏡頭或多鏡頭。分組依因果敘事、時序可行性、介面模式支援度、資產明確度與重試成本彈性劃分，非機械化一鏡一拆或無條件合併。
2. **起始狀態與請求自洽**：每個請求必須自洽描述起始狀態與提交資產，禁止跨請求隱含上下文。角色身分卡或道具卡僅代表外觀基準，單憑身分卡不足以承載前段時序狀態；時序延續須於請求中完整重述起始狀態，或由實際提交之首幀/接續首幀（continuity frame）提供，純文字或 T2VA 生成不強制提交圖像資產。
3. **工作流控管政策**：I2VA / FL2VA / L2VA 關鍵幀生成採單鏡頭控制為內部作業流程規範，非模型能力上限宣稱；Ref2VA 參考模式在驗證介面支援時可支援多鏡頭連貫。
4. **正則提示詞默認自然短段落**：提示詞默認以簡潔自然短段落陳述必要場景與起點、主體核心動作、實用運鏡、逐字對白與環境聲；不強加無意義的焦段與鏡頭黑話。
5. **傳統六欄位為選用工具**：傳統分鏡欄位（畫面、鏡頭、運鏡、動作、臺詞、光線）僅在複雜調度或提示詞精確控制需要時選用，絕不強制填滿無效空欄或套話。
6. **製作元數據嚴格置外**：組編號、劇情梗概、製作筆記、QA 驗證與提供者回執一律置於可複製提示詞外部，不干擾模型解析。
7. **對白與音訊鎖定**：對白嚴格維持逐字原樣（verbatim）；依使用者指示配置背景音樂與字幕需求，不預設立場。時間對位需要時以 0.5 秒為參考刻度。
8. **資產綁定規範**：提示詞內僅引用本請求實際提交之素材，別名代幣（`@資產名 `）後置空格；無對應素材時以客觀純文字描述，草稿待補項標於外部筆記。
9. **寫作路由**：實質文案與修訂由 Antigravity 主導；僅在 CLI 缺失或額度確定耗盡時降級交由 Codex 接管（權限、網路、頻率限制與審查阻斷不觸發降級）。Codex 負責編排、程式碼與審查；原生環境不遞歸路由。
