# ai-film-skills 首次使用的版本檢查

由主代理在本次對話第一次實際使用套件內任一 Skill 時檢查。先定位這次載入的 Skill 目錄，同一對話只檢查一次；換 Skill、交接子代理或呼叫無工具寫作代理時沿用檢查結果。另一個對話重新檢查。將結果記在本次對話的工作狀態，與作品正文及模型提示詞分開。

## 查核版本

1. 若可執行本套件的 `screenplay-director/scripts/check_skill_update.py`，以 Python 3.9 以上執行，位置參數填**這次載入的 Skill 目錄**。它讀取 Git 檢出版本，或獨立複製時的 `.ai-film-skills-revision`，並用公開 API 比對 [上游 main](https://github.com/shoung/ai-film-skills/commits/main/)。檢查只讀取本地資訊與遠端提交。
2. 若沒有共用腳本、Python 或 Shell 網路，使用可信的 GitHub 工具讀上游 main。可用確定的本地提交與上游做祖先或 [GitHub compare](https://docs.github.com/en/rest/commits/commits#compare-two-commits) 比對。若找不到本地版本或無法驗證遠端，簡短說明後繼續當次工作。版本不明時不得宣稱有新版或已是最新版。
3. Git 提交識別的是安裝基準。個別工作區檔案可能另有尚未提交的修改。

## 依結果處理

- `update_available`：在開始原任務前告知本地與上游的短提交識別碼，問使用者「要先更新 Skill，還是用目前版本繼續？」等使用者決定或沿用本次已明確授權的選項。使用者選擇沿用時，本次對話不再提醒。
- `current` 或 `local_ahead`：繼續原任務。
- `diverged`：說明本地與上游各有提交，如需更新先確認要保留的分支與安裝來源。
- `unverified`：用可信的可用工具補查一次。仍無法確認時簡短揭露原因，繼續原任務。

使用者同意更新後，先確認操作的是實際安裝來源與預定分支，檢查工作區有沒有未提交修改和衝突。乾淨、受追蹤且可快轉的 Git 安裝，可依既有更新方式快轉；獨立複製則依原本的安裝方式更新對應目錄和來源版本。發現本地修改、分支分歧或來源不明時，保留原檔並請使用者決定如何處理。更新後核對已載入的文件位置與目標提交，重新讀取工作所需規則。
