# 參考圖控制規範 (Reference Control Specification)

本規範定義 AI 影視製作中「表外參考計畫」（Reference Plan）之格式標準、狀態生命週期、控制邊界及雙軌品質審查（QA）流程。

## 1. 表外參考計畫表規格

為維持八欄分鏡表之純粹性，圖像參考計畫獨立建置於表外旁表，標準表頭格式如下：

| 鏡號 | 順序 | 狀態 | 來源 | 用途 | 控制 | 不得控制 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `01` | 1 | `actual` | `assets/characters/hero_card.png` | 外貌 | 五官特徵、臉型輪廓、固有疤痕 | 歷史姿態、瞬時表情、光影方向 |
| `01` | 2 | `planned` | 待製作的場景圖條目 SCENE-HALL | 空間 | 建築架構、透視進深、陳設布局 | 臨時人物、動態特效、特定機位 |

### 狀態定義
* **`planned`（規劃中）**：尚未核對實體圖像之掛圖計畫，表示該鏡頭預計採用特定參考圖。
* **`actual`（實體已確認）**：實體圖檔已實際存在、可讀取、經檢視確認品質，且具備正式資產卡對應。

> [!CAUTION]
> * **嚴禁符號外溢**：嚴禁將 `[PLAN]` 或佔位符填入可提交之 prompt、資產卡定義或 `generation.image_inputs` 中。
> * **嚴禁虛假標記**：處於 `planned` 狀態之項目絕不可標記為 pass。
> * **缺圖阻斷機制**：實際提交生圖前必須逐圖檢核實體檔案、順序標籤與檔案雜湊值（Hash）。若缺少必要參考圖，立即標註「不可提交」，嚴禁私自偷偷改為純文字文生圖。
> * **草圖整批停止規則**：執行 `storyboard-grid` 時，缺少分鏡表、必要正式資產卡或必要實圖須整批警示並停止；此門檻不擴大為所有純文字分鏡或 T2VA 任務都必須備圖。

## 2. 圖像用途分類與控制邊界

每張參考圖的主要用途必須唯一，次要補充範圍應於旁表備註說明。本規範不強制每鏡皆需全身卡或固定圖數：

* **外貌**：控制五官比例、年齡感、固有生理特徵；**不得控制**歷史劇照中之特定姿態、瞬時動態或非常態光影。
* **造型狀態**：控制特定戲段之服裝剪裁、戰損程度、泥污血跡、特定妝髮；**不得控制**竄改角色之基礎身分與骨骼結構。
* **空間**：控制空間幾何構造、建築風格、主要陳設布局；**不得控制**將場景參考圖內偶發之臨時人物導入畫面。
* **構圖**：控制視覺引導線、畫面分割比率、主體透視角度；**不得控制**強加具體角色之精細容貌細節或道具材質。
* **尺度**：控制人物與場景建築、道具之間的相對比例參照；**不得控制**具體動作路徑。
* **效果**：控制法術光效、煙霧粒子、光影濾鏡氛圍；**不得控制**改變場景實體硬體幾何與角色身分。
* **風格**：控制筆觸質感、顆粒度、色調與渲染風格；**不得控制**偏離或改動既定劇情實體與人物設定。
* **首幀／尾幀**：控制鏡頭起點或終點之精確構圖與角色姿態；**不得控制**在首幀偷跑動作，或在尾幀延遲終止。

## 3. Package Schema 映射規範

實體輸入嚴格遵循 `package-schema.md` 所規範之現有角色欄位：
* `first_frame`
* `last_frame`
* `identity_reference`
* `scene_reference`
* `prop_reference`
* `composition_reference`

細分用途（如戰損造型、光影參照）於表外旁表說明，嚴禁擅自發明非標準之 schema role，嚴禁以 `planned` 假冒實體檔案。原本任務若允許純文字 T2VA，仍可按既有規則產製提示詞，不把參考計畫強制加到無圖任務中。

## 4. 提示詞鎖定短語與外觀重述

* **鎖定短語**：針對跨鏡不變之關鍵特徵，可按需選用少量「鎖定短語」錨定控制範圍。
* **外觀明確重述**：未由實體參考圖直接提供之關鍵外觀特徵，應於 prompt 中明確重述。
* **反對盲目拼貼**：並非要求在已有實圖時也重複貼上整套資產卡描述，更不能僅憑提示詞字面相同即推定像素層級的一致性。
* **語法與能力邊界**：引用圖片或音訊應嚴格按照目標模型之序號語法與實際支援填寫，未經驗證之互斥模式或秒數上限不能當成官方能力宣稱。

## 5. 雙軌 QA 審核機制與失效規則

品質管制維持獨立雙軌審查：
1. **盲審軌（Blind Review）**：僅檢視該 prompt 本身與實際提交之素材檔案、模型參數設定，驗證提示詞自足性。
2. **製作審查軌（Production Review）**：綜觀全劇脈絡、八欄分鏡表、資產卡與表外參考計畫旁表，驗證上下文連貫性。

### 審查區分與重審機制
* **狀態審查區分**：規劃狀態（planned）QA 與可提交提示詞（actual）QA 嚴格區分。
* **語意失效重審**：凡修改 prompt 文字、替換素材、變更順序或調整角色控制範圍，即依既有簽章及人工語意失效規則重審；嚴禁私自修改正式資產卡迎合錯誤圖片。
* **簽章防偽維護**：既有 `prompt_signature` 涵蓋實際綁定資料；旁表語意若有變動，不得僅修改 hash 假裝審核通過。
