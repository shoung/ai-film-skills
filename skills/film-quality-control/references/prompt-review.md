# 提示詞審核規範：雙軌審核與獨立簽章

每個可提交的影片生成請求都需經獨立盲審與製作審核。

## 1. 雙軌審核架構與審核順序
提示詞交付前必須通過兩條審核軌道。執行時**必須先在全新隔離環境中進行盲審獨立請求審核，隨後再進行具備全局視野的製作品管審核**。兩項審核可由同一名具備唯讀權限的獨立品管人員（`reviewer_role: "independent_qa"`）依序完成；若無可用審核員，狀態應標記為 `pending`，嚴禁偽造第二代理人或審核人證據。

### 軌道一：盲審獨立請求審核（Blind Isolated-Request Review）
審核員置於**隔離環境**中，僅提供：該生成請求 prompt、隨附資產（`image_inputs`、`text_reference_bindings`）與參數（mode、duration_seconds）。**嚴禁提供全片劇本、前後其他請求 prompt 或外部備忘錄**。
審查項目：
1. **文本自足性（self_contained）**：無未說明的隱形假設或未定義動機，顯式建立起始狀態（僅提交角色或道具卡不提供先前時序狀態）；無跨請求未提交之引用。
2. **未解析代號與參考綁定（reference_binding）**：正文中所有 `@alias`、`<Subject N>`、`<Picture N>` 均能在隨附資產中解析，無懸空標籤。若包含音訊或視訊參考，因 package schema 僅支援圖像，應發出警告並附人工評估證據，不可偽造為圖像資產；機器警告需以人工情境證據判定，而非一律硬性阻擋（hard block）。有發話時，人工核對開頭參考區的角色、聲線、音訊標籤與實際上傳檔，確認發話處用同一角色對照。製作備註記錄待上傳的音檔與標籤，交付可提交版前再核對實際附件。
3. **可讀性與無衝突（readability）**：主要動作鏈清晰，運鏡描述易讀；無堆砌無意義焦段（mm）或黑話，無微動作填料，時間節拍明確；無互相矛盾的空間方位或肢體衝突，單鏡模式下無暗藏切鏡。
   - **畫面座標與方位一致性檢查**：審查提示詞是否以觀眾視角的畫面上下左右為準，並確認人物肢體與畫面方向指代清晰、換機位或切鏡後空間關係已重建。若出現以羅盤方位直接指揮位置或動向，應退回人工修正；台詞、招牌或地名等非位置用途之原文則予保留。

### 軌道二：製作品管審核（Production Review）
審片員立足全劇本、八欄分鏡表與資產清單，進行上下文貫通檢查：
1. **分組邏輯（grouping）**：審查多鏡合併或單鏡拆分是否具備敘事因果、對白動作時長可行性、驗證之模式能力、重抽成本與素材清晰度之合理解釋；確認分組為合理決策而非機械套用。
2. **鏡頭覆蓋度（coverage）**：八欄分鏡表中的每一列連續鏡頭均被對應的生成群組覆蓋，無遺漏鏡頭，無未登錄的偷渡切鏡。
3. **台詞對齊（dialogue_alignment）**依[生成前鎖定台詞對帳](locked-dialogue-reconciliation.md)逐句比對鎖稿、分鏡與各請求實際準備送出的正文。核對說話者、原文、順序、重複、遺漏與跨鏡片段，並將範圍、來源版本及結果寫入 `production_evidence`。依 [模式選擇規則](mode-and-shot-rules.md#生成模式選擇) 檢查含有分鏡安排發話之鏡頭的請求均用 Ref2VA，包含後製承接的畫外音與旁白。同一請求內可包含因敘事需要合併的無發話鏡。請求所含各鏡在分鏡的聲音設計皆無發話時，若用 Ref2VA，須說明兩種關鍵幀方案不可行的原因。
4. **連續性（continuity）**：跨請求承接狀態合理，道具狀態、角色服裝、站位與軸線前後呼應。
5. **時長可行性（timing_feasibility）**：依 [台詞與時長審核](timing-and-dialogue.md) 評估發音字數、語速、呼吸停頓與動作耗時，確保指定秒數切實可行。

## 2. 審核角色與責任隔離
- 審核員身分標記為 `reviewer_role = "independent_qa"`，採**唯讀模式**：僅出具審核結論、問題清單與修復建議，`reviewer_id` 不得與 `producer_id` 相同，**嚴禁自行修改提示詞正文、分鏡或劇本**。
- 實質修訂依 [本技能入口](../SKILL.md) 的寫作分流執行，完成後交審核員重審。
- 審核紀錄、品管憑據與製作備忘保存在獨立 QA 報告中，嚴格置於模型提示詞正文之外。

## 3. 審核紀錄與失效

以 [提示詞審核模板](../assets/prompt-review-template.json) 保存 `prompt_review`。草稿缺審核或簽章不符時有警告。交付模式要求 `pass`、現行簽章及真實證據，欄位及簽章計算見 [登錄格式](package-schema.md#generations)。

- `production_evidence` 記錄製作審核觀察、群組、版本及鎖定台詞對帳。
- `isolation_evidence` 記錄只依當次提示詞、附件與參數得出的獨立盲審觀察。

純提示詞交付無需生成靜幀。宣稱可提交的圖像模式須核對本次實際要使用的附件，計畫素材依 [參考圖控制](reference-control.md) 登錄。工具警告由審核者根據實際證據判定。

提示詞、模式、分組、時長或素材綁定改動後重審。鎖稿、分鏡與音訊／視訊等人工核對來源另記版本，變更時依影響範圍更新審核。
