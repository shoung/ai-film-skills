# 原版等價創作台與八欄分鏡設計

## 需求與基準

使用者要求與 drama-skills 原版創作台功能等價，儘可能復刻 UI；閱讀分鏡時能同時看圖與提示詞，維持既有八欄資訊。承接上一輪差異盤點與既有原著分析／創作台設計，這次以完整移植為目標，不再以精簡自製頁面取代原版功能。

基準固定為 drama-skills commit `37232f6d22e174c36e321d2e3a1a3ae871e7d602` 的根目錄 DESIGN.md、short-drama dashboard 靜態資源、creator_views.py 與 dashboard_server.py。功能等價指該版本創作台已實作的使用者操作與呈現，不擴張為上游整套生成／剪輯 CLI。若發現設計文件與原始碼不一致，記錄實際實作與差異，不虛報完成。

## 方案

1. 在現有精簡工作台逐項補功能：需重寫大部分 UI，容易再次遺漏原版互動，不採用。
2. 移植原版完整 UI 與需要的呈現模組，另接本套件資料適配層：最接近原版，採此方案。現有安全服務與保存契約保留或等效移植，避免引入多餘生成能力。
3. 強迫全部專案改成原版五文件格式：會破壞八欄與既有專案，不採用。

此方案與前輪建議一致；具體檔案拆分、內部轉接函式由實作者決定。MIT 來源、原始 commit、修改說明與授權一併保留。

## 必須等價的功能

- 頂部專案／分集切換、七階段導覽、全劇總覽、八項製作進度矩陣與可說明原因的下一步待辦。
- 劇本紙面視圖與場次定位，人物／造型／場景／道具結構卡及可追溯來源。
- 分鏡卡片／表格、節奏時間條與指標、單鏡詳情、上下鏡切換及相關設定／審查連結。
- 圖片／影片提示詞專用視圖、完整展開與複製、可複製的助手請求。
- 成片播放器與五軌剪輯時間線；無剪輯資料時呈現缺項，不能製造軌道內容或假成片。
- 審查問題卡、分級、定位、修改建議與複製修改請求；維持獨立 QA，不能在 UI 點擊通過。
- 全域搜尋、hash 深連結與瀏覽器前後頁、文件檢視與按鏡號／標題定位原文編輯。
- 主題切換、鍵盤搜尋、上一鏡／下一鏡、Esc、Ctrl/Cmd+S；原版桌面／窄版版面及可及性。

## 圖與提示詞的核心閱讀方式

桌面保留原版七階段外殼及分鏡主畫布；選鏡後的詳情區採圖片與提示詞並排，令使用者不離開同一鏡就能比較。圖片提供首幀、尾幀、參考設定卡與可用分鏡草圖；提示詞提供畫面 prompt、首／尾幀提示詞及實際影片提示詞，分別標明來源。提示詞可展開全文及複製；媒體可放大或播放。

單鏡詳情同時保留原版起始幀、成片片段、台詞、出場設定、提示詞與關聯審查內容，無資料時明示缺項。切換鏡頭時圖、提示詞、鏡號及審查同步更新，禁止前一鏡殘留。沒有單鏡圖時明示缺少；只有 25 宮格時顯示對應整張草圖與鏡號範圍，不把整張冒充單鏡圖，不自動生圖或隨意裁格。窄版改為同一詳情內上下排列，不另開文件才能讀提示詞。保持原影片橫／直尺寸比例，不強制 9:16。

## 八欄與舊資料適配

正式主表欄序固定：`編號、畫面描述、攝影機描述、聲音描述、旁白對白、時長、影片生成方式、畫面prompt`。圖片、QA、參考控制與其他附加資訊置於詳情／旁表，不增加第九欄。缺失八欄值顯示未提供，不生成補文。

- 支援標準八欄 MD／CSV，並兼容多「修改」欄的既有九欄文件：映射八欄，修改內容放來源附註；不刪欄、不重寫原始文件。原文編輯仍呈現原格式。
- MD／CSV 同鏡號只建立一組鏡頭，保留各來源；資料不一致要提示差異與來源切換，不能靜默選最新／拼接兩版。有明確製作入口可依其指示選來源；無明確主從時保持待確認。
- 支援根目錄、EP 分集與版本／製作階段目錄，不要求既有專案搬移；不同版本不能混成同鏡頭。
- 依明確登錄、文件連結及有邊界的鏡號命名建立關聯；S01 不得誤配 S010；多鏡影片保留群組關係。衝突候選標示未確認，不假設裁剪版或最後修改者為正式片。
- 設定卡代碼 C／E／P、逐鏡首尾幀、H3 分組提示詞、中文 25 宮格命名與既有生成紀錄均納入適配。標記關聯證據與來源，不能把推測當實際生成素材登錄。
- 舊 QA 與正式四陣列 QA 套件分開呈現；舊紀錄可閱讀，但不提升為已通過的正式 QA。HTML 總覽提供安全隔離預覽或來源入口，不執行任意腳本／遠端內容。

## 實作邊界

在後端增加 view-model adapter 與原版前端 API facade，集中供應 projects/status/tree/series/episode/search/file/media；不將契約轉換散入各個畫面。內部 shot 仍保存八欄 `fields`、來源與行位置，原版分鏡的 start/action/end 等欄不能反向取代八欄。明確轉接上游 `expectedVersion` 與本套件 `expected_version` 的保存契約，媒體資訊／位元組端點及 Token 名稱也由單一 facade 處理。

Python 標準庫與原生 HTML/CSS/JS，沿用現有啟動 CLI，維持本機 loopback、Token／Cookie、Host／Origin 核對、路徑與 symlink 防護、Range 播放、版本衝突與原子保存。資料來自專案原始檔，不產生第二套創作真源。初次載入及唯讀瀏覽不改使用者專案；編輯必須由使用者明確保存。

在 `ai-film-skills-publish` 實作並同步 `ai-film-skills` 使用副本，保留原著分析及其他 skills。除本地啟動供試用外，不自動生圖、生成影片、執行付費接口或推送遠端。移植所需上游模組逐個盤點依賴，不把完整不相關工具鏈包入。

## 驗收與獨立 QA

建立逐項功能等價矩陣，每項必須有原版來源、實作位置、操作證據與通過／缺項狀態，不以行數或合成測試數量代替功能等價。

1. 單元／API 回歸涵蓋八欄、九欄映射、MD／CSV 差異、版本隔離、提示詞拆分、鏡號邊界、多鏡影片、缺檔、舊 QA、保存衝突與安全邊界。
2. 使用同一組公開／合成資料分別開原版及移植版，逐項操作七階段、搜尋、主題、深連結、圖／詞、時間線與編輯，比對桌面和窄版截圖；不能以只讀程式碼替代此驗收。
3. 《放手，讓你好走》作為唯讀真專案驗收：辨識現有 54 個不同鏡號、顯示來源衝突、中文宮格、設定卡、首尾幀、H3 提示詞與影片候選；抽查跨組鏡號及首尾鏡，驗證圖詞不錯配。盤點前後雜湊，確認沒有改動來源。
4. 乾淨 Luna QA 子代理獨立重跑必要單元與瀏覽器 E2E，特別驗證每鏡圖與提示詞同屏、精確八欄、無資料時不假造、QA 不被介面批准。
5. 有任何原版功能未完成或無法驗證，明列阻塞，不能宣稱功能等價已達成。完成後開啟更新創作台供使用者試用。
