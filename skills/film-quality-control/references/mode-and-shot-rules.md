# 分鏡表、單幀與影片提示詞的對應

## 一鏡的定義與八欄分鏡表
一鏡是由同一機位或連續運動攝影機拍下的連續時間／空間。平移、推近、連續環繞、由物件移焦到人物，均屬單鏡；切換機位、越肩反打、插入特寫畫面再切回、跨時空蒙太奇則是多鏡。分析時先理解提示詞語意，再核對 Shot 標籤。角色對視、轉頭或台詞換人，本身不必然切鏡。
分鏡表保持原有八欄，每列恰為一個連續鏡頭，使用 S001、S002 等穩定鏡號。生成請求（Generation Request）是提示詞製作、提交與品管審核的基本組織單元，一個生成請求可包含單一鏡頭或多個連續鏡頭。拆鏡後應核對動作接續、視線方向、鎖定台詞與總時長，不可憑空增補鏡頭遷就尾幀。

## 生成請求為組織單元與分組準則（Grouping Criteria）
分組為綜合權衡之合理決策，絕非機械化「一鏡一請求」或「同場景必合併」。各項規則為原則性偏好，非絕對強制；例如同場景可因重抽成本拆分，蒙太奇可依敘事節奏合併。分組評估準則如下：
1. **故事因果與連貫性（Story Causality）**：同場景緊密相連之動作鏈、對話呼應或動態銜接，偏好合併以維持連貫；跨場景跳接、大幅視點跳躍或敘事斷點偏好拆分，但關聯緊密的節奏蒙太奇亦可合理合併。
2. **對白、動作與時長可行性（Timing Feasibility）**：考量完整台詞、發音節奏、反應留白與實體動作總時長。若預估總時長超出所選介面或模式的實際處理能力，應主動拆分（不設定或假設未經證實的模型穩定秒數區間）。
3. **驗證之介面與模式能力（Interface & Mode Capabilities）**：以實際介面與模式之確認能力為準。I2VA、FL2VA、L2VA 依工作流可靠性政策限單一連續鏡頭；需多鏡切換者應採多鏡模式（如已驗證之 Ref2VA、T2VA）或拆為逐鏡請求後剪接。
4. **控制與重抽成本（Control and Retry Cost）**：高度依賴精細物理互動、複雜道具操作或關鍵情緒特寫時，偏好拆分獨立請求，避免單點動作瑕疵導致整段多鏡反覆付費重抽；一般穩定對話則可合併。
5. **素材清晰度（Asset Clarity）**：需嚴格錨定特定角色身份、服裝狀態或道具特徵時，獨立請求可使首幀或參考資產綁定更單純聚焦。

## 請求自足性（Request Independence）
每個生成請求必須完全自足：
- 必須明確建立起始狀態（如人物起始站位、視線、道具初始狀態），除非本次請求確實提交了提供起始狀態的首幀或接續幀。僅提交角色卡或道具卡**不提供先前時序狀態**，只有實際提交之素材方具約束力。
- 包含本次生成所需的顯式資產綁定、視覺描述、音訊環境與動作指引。非提示詞內容（製作備忘、QA 紀錄、提供者憑據）一律置於可複製 prompt 之外。
- **請求內回指**：同一請求內後鏡可合法承接前鏡（如同提示詞中 [Shot 2] 承接 [Shot 1] 提起之物件）。
- **跨請求回指**：嚴禁直接引用未隨本次請求提交的外部鏡號或未定義情境；顯式資產綁定（如 `@角色名`、`<Subject 2>`）本身不提供先前時序狀態，每個請求必須明確陳述所需的起始狀態，除非本次請求確實提交了提供起始狀態的首幀或接續幀。不可假設模型具有跨請求隱性記憶。
- 劇本中鎖定台詞必須原樣精確保留，不可擅改或漏句。提示詞正文依使用者語言（繁體中文），模型欄位鍵名與控制語法維持原樣。

## 模式門檻與工作流可靠性政策
| 模式 | 本流程准許鏡頭數 | 圖片用途 |
|---|---:|---|
| T2VA 文生影 | 一鏡或多鏡，依驗證之目標模式能力 | 不帶圖片；需固定角色身份且有可用模式時改採參考模式 |
| I2VA 首幀圖生影 | 恰一個連續鏡頭 | 一張 first_frame，作為該鏡實際起始畫面 |
| FL2VA 首尾幀圖生影 | 恰一個連續鏡頭 | 一張 first_frame 與一張 last_frame；同鏡可連續到達的前後狀態 |
| L2VA 尾幀圖生影 | 恰一個連續鏡頭 | 一張 last_frame；僅在目標模型確認支援此模式時採用 |
| Ref2VA 參考生影 | 一鏡或多鏡，依目標模型能力 | 身份、場景、道具或構圖參考；Ref2VA 綁定身份／場景參考可支援多鏡，各圖用途明確，不承諾硬性首尾幀 |

**邊界說明**：本流程對 I2VA／FL2VA／L2VA 實施單一連續鏡頭要求，屬於**內部工作流可靠性政策**，並非對底層模型官方極限能力的全面性宣稱。不可向使用者虛構未經驗證的多鏡首尾幀能力。
I2VA／FL2VA／L2VA 正文中不得包含肯定的切鏡指示（如「切到／反打／jump cut／montage」等）。否定語句（如「不要切鏡」、「no cuts」）不屬於切鏡指示。多鏡需求應改採已驗證之多鏡模式，或拆為單鏡生成後剪接。

## 圖與提示詞逐鏡核對
- 首幀必須對應動作起始點；尾幀對應動作收束狀態。若台詞觸發後才產生反應，首幀不可提早出現該反應。
- 反打屬不同鏡號；雙人對話的左右位置、視線與攝影軸線應合理銜接。景別按敘事需求安排，避免機械式全部中景。
- 道具特寫可將身份／妝造檢查標記為有說明的 N/A；特寫鏡頭背景被裁切不屬場景錯誤，但可見幾何、光源與材質需一致。
- 畫面比例與構圖依專案規格設定，不可將直式素材硬壓扁至橫式。
- prompt 的模式、shot_ids、圖片標籤、對白角色、時間碼與起始狀態需與分鏡表及資產登錄完全一致。

## 示例（格式示範，非實際生成／QA 紀錄）
以下皆為合成之格式說明示例，非真實執行通過紀錄：
- **合規單鏡 FL2VA 示範**：G001 包含 S001。小琪在單人近景中自平靜聆聽至挑眉反應，鏡頭緩慢推近，全段無切鏡，首尾幀皆為同機位連續可達之狀態。
- **不合規 FL2VA 示範**：標記單鏡 [Shot 1]，但描述中要求「第 3 秒切反打看朋友，第 5 秒切回小琪」；此為多鏡動作，不符合單鏡政策，應拆為 S001–S003 或改用多鏡模式。
- **合規多鏡 Ref2VA 示範**：G001 包含 S001（小琪近景）與 S002（朋友越肩反打）；分別綁定角色卡與場景參考卡，正文逐鏡指示視線與機位，不保證硬性首尾銜接。
- **合規獨立請求接續示範**：G002 描述開盒，起始狀態寫明「小琪坐在桌前，桌上置有已關閉之木盒，雙手懸停於盒沿」，綁定角色卡與道具卡，無跨請求懸空鏡號引用。
