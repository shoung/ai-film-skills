# 劇本寫作

本次對話首次使用時，由主代理依 [版本檢查](../screenplay-director/references/skill-update-check.md) 核對一次。單獨安裝時，以實際安裝的 Git 提交或 `.ai-film-skills-revision` 比對 [上游 main](https://github.com/shoung/ai-film-skills/commits/main/)。有新版先確認是否更新，無法驗證則簡述後繼續。

## 全新劇本的入口

直接收到全新劇本委託時，依 [共用啟動訪談](../screenplay-director/references/startup-intake.md) 沿用核准創作綱要和授權。單獨安裝時先查資料，把可獨立回答的關鍵缺項列在同一輪，首輪通常 2–4 題，各題附建議與理由。若只有一個前提可先決定，先問一題。等回覆後，再問依賴前輪答案的問題。方向摘要確認或已有直接開工的授權後，按本案材料寫作。缺共用識別資產時，新創作只在對話中顯示一次 `SHOUNG`，續作、維護或一般交接不重複，標記留在交付物外。已有劇本的續寫、局部改稿或純格式轉換直接依材料與指定範圍處理。

## 依交付選擇寫作方式

創作正文、續寫與實質修訂依 [antigravity-writer](../antigravity-writer/SKILL.md) 分流。單獨安裝時用 [寫作備援](references/writer-fallback.md)。

- **初稿、續寫、改稿與台詞整合**依 [寫作與修訂](references/writing-workflow.md) 選讀相應分支。可直接沿用使用者提供的綱要、既有稿或等效設定。只補問會改變本次交付的缺項，單一角色或局部修訂按現有材料辦理。只整合已採納的修改，維持未授權改動的情節、人物關係、場次及鎖定台詞。
- **新稿格式或轉檔**讀 [劇本格式與製作交接](references/script-formats.md) 的相關段落。既有稿沿用核准格式；新稿按交付選標準影視、小說化敘事或中文拍攝稿。分集是可套用於不同格式的組織方式。使用者指定的格式、節奏與集數直接沿用。

連載分集的擴寫與敘事修訂，依 [連載分集規劃與驗收](../screenplay-framework/references/serial-episode-planning.md) 讀取核定大綱、鉤子紀錄與可得的相鄰集，將局部兌現與承接寫進正文。按本案時長及表演節奏編排，完成後做正文冷讀，更新鉤子兌現與待查項。單獨安裝時，把本集目標、阻力、換策與結果，前後集的狀態和第一個承接動作，以及主要鉤子的設置、預計和實際兌現位置記入既有創作筆記。原著改編另核對必留事件、來源與知情進度。只有製作者可讀稿時以「製作者自查」記錄，缺相鄰集正文則標待驗。

需要審稿時按委託交 [劇本醫生](../screenplay-doctor/SKILL.md) 或 [台詞專家](../dialogue-expert/SKILL.md)。使用繁體中文，接受繁簡同義指令，保留原稿指定語言、口音及鎖定文字。
