# 精簡生成提示詞格式

本規範優先於舊指南中衝突的格式、時間精度與篇幅要求。這是本技能組的預設交付格式；使用者明確要求的語言、鎖定區域及已驗證的模型介面限制優先。

## 1. 生成請求為獨立單元與分組原則

- **獨立單元**：影片生成提示詞（Generation Request）是獨立生成與交付的基本單元。一個提示詞可包含單一鏡頭或多個連續鏡頭。
- **八欄分鏡對應**：分鏡表始終維持每列一個連續鏡頭；生成請求在旁表中可對應一列（單鏡）或多列（多鏡）。
- **分組決策五維度**（非機械式合併或拆分，禁止自動一鏡一請求或同場景無條件合併）：
  1. **敘事與因果關係**：同一事件、緊密因果或連續動勢適合合併；情節轉折、重大時空跳躍或不同敘事焦點適合拆分。
  2. **對白、動作與停頓時間**：評估發話、反應與物理動作停頓之實際可行性，並結合已驗證介面之時長限制進行評估與合理切分。
  3. **模型與模式可用性**：依據目標模型在已驗證介面中的單次生成片長上限與模式支援度決定。
  4. **素材清晰度**：涉及特定角色正面或核心道具特寫時，拆分獨立請求有利於明確綁定參考資產。
  5. **控制與重抽成本**：複雜動作或高精度鏡頭偏好獨立成段以降低局部瑕疵重抽成本，但此偏好應與連貫性需求權衡，非強制每個複雜動作皆須切分。

## 2. 單鏡工作流策略與多鏡能力

- **單鏡工作流策略**：在圖像引導模式（I2VA / FL2VA / L2VA）中維持單一連續鏡頭，屬於本團隊之**工作流管理策略**，用以確保首尾幀控制精度，而非宣稱模型絕對無法支援多鏡。
- **多鏡能力邊界**：純文字（T2VA）與全參考（Ref2VA）模式中，只要在已驗證之模型時長與語法支援範圍內，可透過角色／場景資產引用支援多鏡頭連續敘事。

## 3. 請求自足性（Self-Contained）與資產引用

- **完全自足**：每個獨立請求必須包含該段生成所需的全部要素（綁定資產、風格、聲音與起始狀態）。外界全局設定不會自動提交至模型，不可假設模型具有跨請求記憶。
- **請求內回指（In-request backward references）**：在同一提示詞內，後鏡回指前鏡（如「Shot 2 承接 Shot 1 已開啟之櫃門」）只要語意清晰即為合法。
- **跨請求回指限制**：嚴禁在正文中抽象引用未提交的前案鏡號（例如「承接請求 A 的鏡頭 1」）。僅有本次請求實際提交的參考資產才具效力；單純的角色卡或道具卡**不提供歷史時間歷程**。
- **明確起始狀態**：每個請求必須在正文開頭明確描述初始可見狀態（例如物件所在位置、雙手尚未接觸或已持有道具），除非本次請求確實提交了提供該狀態的真實首幀／連續幀。

### 畫面方位

- **畫面視角與深度**：構圖、人物／道具位置、動向、視線、光線與運鏡，一律以當前鏡頭觀眾所見的「畫面上下左右／中央」為基準；空間深度可用「前景／中景／背景」或「朝鏡頭靠近／遠離」。
- **嚴禁羅盤指令**：禁止以東西南北、東北／西南（含英文 north/south 等）指揮畫面位置或運動。原台詞、地名、招牌或地圖文字可保留；地理設定可記於製作筆記，但正文須以可見構圖為錨點。
- **禁止機械換算**：不可機械套用「東=右、北=上」。須依已確認構圖、參考圖或已知機位換算；未知時以可見物作錨點，關鍵方向無法判定時應提問確認，不捏造映射。
- **動態換機重建**：切鏡、反打或環繞後，須依新視角立即重建畫面空間關係，不可將世界方位或前鏡左右視為固定座標；自然運鏡僅描述必要變化。
- **區分肢體與畫面**：人物自身的左手／右手等生理部位指示應正常使用，但須與「畫面左／右」明確區分，避免指代歧義。

**示例**（前提：已確認該場景窗戶位於畫面右側）

- ❌ 反例：陽光自東側窗戶照入，角色走向東側。（誤用羅盤方位）
- ✅ 正例：陽光自畫面右側窗戶照入，角色朝畫面右側窗戶走去。

## 4. 語言、控制語法與精簡表演原則

- **語言規範**：提示詞內文一律依照使用者指定語言（本規範使用繁體中文）。模型專屬欄位標籤與控制語法（如 `<d>[Chinese] ...</d>`、`(S1)`、`[Shot 1]`）必須維持原樣英文字元。
- **內部規劃 vs 提示詞正文**：創作者可在內部構思角色動機、刺激觸發、停頓與呼吸節奏，但提示詞正文**僅列印呈現因果動作或防止模型已知錯誤所必需之提示**。
- **單一主幹動作鏈**：預設一條乾淨的生活或戲劇動作鏈。不強制六行結構，不設定字數下限，不堆砌鏡頭焦段毫米黑話（如 50mm / 85mm），不加入編號子節拍。
- **拒絕微動作填料**：禁止為了填塞秒數而製造無目的眨眼、抓衣角、頻繁吞嚥或隨機身體晃動等無效填料。

## 5. 時間節拍與介面極限

- **0.5 秒時間網格**：敘事時間切點預設以 0.5 秒為最小單位（0、0.5、1.0、1.5……），不產生如 5.8 秒等無效小數點。
- **保留時間戳記語法**：模型若要求指定時分秒時間格式（如 MiniMax H3 之 `00:00.000`），依其語法精確呈現。
- **時長上限依循已驗證介面**：所有指定時長與上限僅依賴已驗證介面的實際能力，不臆造未驗證之極限。
- **鎖定對白逐字保留**：對白文字與鎖定時長必須完全保留，未鎖定部分以自然物理動作耗時為準。

## 6. 撰寫路由與降級原則

- **Antigravity 優先**：提示詞撰寫與實質性內容修訂一律優先由 Antigravity 執行；在原生 Antigravity 環境中無需進行自我遞迴路由。
- **Codex 降級限制**：僅在 Antigravity CLI 缺失或確認配額完全耗盡時，方可降級由 Codex 執行撰寫。
- **錯誤阻斷原則**：認證失效、網路錯誤、頻率限制、請求超時、權限不足或內容審查攔截屬於阻斷事件，應直接回報並停止，不得藉此擅自降級至 Codex。
- **Codex 職責範圍**：Codex 可負責流程編排、代碼編寫與審查，但實質提示詞創作仍依上述規則分工。

## 7. 製作備註與提示詞正文分離

- 群組 ID、八欄分鏡對照、剪輯估值、素材登錄 ID、時長驗算與分組理由等製作備註，一律放置於可複製提示詞正文之外，禁止混入模型輸入。
- 嚴禁捏造虛假 PASS 或生成驗收紀錄；所有範例均為合成示範，非實際執行生成紀錄。
