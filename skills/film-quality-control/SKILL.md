# 影像製作品管

依本次交付範圍檢查，不自動擴大成生圖或生影任務。純劇本、純分鏡表或純提示詞可只做結構檢查；沒有圖片不能聲稱視覺 QA 通過。使用者既有核准與鎖定條件持續有效。

## 四項交付門檻

1. **鏡頭與生成模式相容**：分鏡表每列是一個連續鏡頭；一次生成可以連結一列或多列，但 I2VA（首幀）、FL2VA（首尾幀）、L2VA（尾幀）只能連結一個連續鏡頭。提示詞暗藏切鏡、反打、插鏡或蒙太奇也算多鏡，不能靠只寫一個 Shot 標籤規避。詳讀 [模式與鏡頭規則](references/mode-and-shot-rules.md)。
2. **交付的每張靜幀有獨立視覺 QA**：實際呼叫 QA 子代理看正式參考卡與生成圖，逐張比對角色、服裝、妝造、場景及前後鏡。可批次派工，每張仍須獨立結論。沒有子代理能力、缺正式來源或無法看圖時，標記待審，不能以自行扮演 QA 代替。執行前讀 [視覺 QA 與修復](references/visual-qa.md)。
3. **版本與審核證據吻合**：用穩定鏡號連結正式資產、生成群組與 QA。修改圖片、正式卡或相鄰鏡頭會使相關舊審核失效，必須重審。沿用八欄分鏡格式，資料放在獨立登錄檔，不增改表格欄位。欄位見 [登錄格式](references/package-schema.md)。
4. **台詞、表演與秒數相容**：只讀審片員必須逐段核對原劇本台詞與 prompt，綜合發音長度、語速、停頓、情緒轉折與動作耗時，檢查時間是否過短或過長。詳讀 [台詞與時長審核](references/timing-and-dialogue.md)。只讀審片員可提出問題與修復建議，不直接改動劇本、prompt、素材或正式卡；由製作者修改後重審。

## 最小執行流程

- 先核對已知規格與正式來源；新案啟動沿用 [導演的缺漏提問流程](../screenplay-director/references/startup-intake.md)。若該 skill 未安裝，就直接確認缺少的目標、交付範圍及正式參考；維護與局部修訂不重新啟動訪談。
- 排好鏡號、角色／服裝／場景／道具狀態，再選生成模式及圖片用途；不把身份參考硬當首幀。
- 需要大量生成時，先選能代表臉部、服裝、場景及正反打的少量試作檢查；在既有授權內執行，不因本 skill 自動發起付費生成。失敗先定位原因再修正，避免盲目重抽。
- 每張圖完成後交獨立 QA。下一張尚未生成時只能暫審卡片與前鏡；序列齊備後補足前後關係，才可列為最終通過。
- 每段 prompt 完成後另做時間可行性審核。純提示詞也需要此項，不因沒有圖片而跳過；沒有可用秒數或無法判斷語速時，先標記待補及假設，不假稱已實測。沒有實際生成請求，不為驗時擅自發起付費影片或語音生成。
- 結構檢查可用下列腳本；再由主代理核對提示詞全文、實際 QA 證據與修復結果。腳本成功只代表資料符合可機讀規則，不能證明人臉相同。

```text
python scripts/validate_package.py /absolute/path/package.json
python scripts/validate_package.py /absolute/path/package.json --delivery
```

第一行驗證鏡號、生成模式及參考綁定；第二行另驗證實際檔案、雜湊與獨立審核紀錄。相對資產路徑以 package.json 所在目錄為準。退出碼：0 通過該範圍，1 檢查失敗，2 輸入無法讀取。沒有正式靜幀的純文字包可通過結構交付，不表示做過視覺審核。

## 交付紀錄

交付時列出實際檢查範圍、通過項目、待審或退件項目、證據路徑。不得把「已寫審核規則」「腳本無錯」「模型說已保持一致」當作視覺通過。若使用者只要提示詞，做結構與台詞時長審核，不強迫建立完整影像包或生圖。

可從 [空白登錄模板](assets/package-template.json)、[視覺待審模板](assets/qa-review-template.json) 與 [時長待審模板](assets/timing-review-template.json) 開始；模板不含任何假通過或虛構代理紀錄。這裡的首尾幀限制是本工作流程的可靠性政策，不冒充所有模型的官方能力邊界。目標模型的可用模式另依其正式規格或對應 skill 核對。
