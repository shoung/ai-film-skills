# 生成前鎖定台詞對帳

逐一核對鎖稿中的發話是否依序落在八欄分鏡與準備送出的模型提示詞。發話包含角色對白、旁白、畫外音，以及劇本要求聽見的其他說話聲。沿用八欄分鏡，在製作旁表或 QA 報告登錄對照。

## 確認本次檢查範圍

| 交付階段 | 對照來源 | 證據能支持的結論 |
|---|---|---|
| 純分鏡或格式轉換 | 鎖稿與本次八欄分鏡，含「旁白對白」與「聲音描述」 | 鎖稿至分鏡的對帳結果 |
| 可提交的提示詞 | 另讀每個生成請求實際準備送出的完整正文，包括用於說話者對照的角色或聲線定義 | 鎖稿至生成請求正文的對帳結果 |
| 核實已提交內容 | 另讀實際送出的正文，或可還原該正文的提交快照、回執 | 已提交內容的對帳結果。若只能看到請求 ID 或送出畫面，正文標待核實 |

記下檔案路徑與版本或雜湊、場次、鏡號、依成片順序排列的請求 ID，以及本次檢查的階段。抽查時明示哪些場次、鏡號或請求未查。若同一鏡有備選請求，依各版本的預定使用順序分開核對。台詞若安排另行錄製或後製播放，記下原句、責任環節與對照證據，保留於分鏡核對中，並在模型正文對帳說明該台詞由其他環節負責。未鎖稿、缺少必要來源或無法解析說話者時，註明缺件與待核對範圍。

## 對帳步驟

1. **從鎖稿列出發話。** 按劇本播放順序列出穩定的場次及台詞 ID、原稿位置、說話者與原句。優先沿用既有 ID。原稿沒有 ID 時，可依場次和場內發話編號登錄（如 `C01-D02`），在同一鎖稿版本沿用。兩次刻意說相同的話，各用自己的台詞 ID。
2. **從分鏡與各請求擷取實際發話。** 分開讀取各階段原檔，自頭至尾列出發話，再對應鎖稿 ID，包含找不到對應的新增句。記錄分鏡的鏡號及欄位、請求的版本及正文段落或時間碼。依同份請求的定義把 `@角色`、`(S1)`、`<Subject N>` 等發話標籤映射回原說話者，記下這個對照。字幕、招牌、動作、語言標籤、音色或表演說明各自依其功能判讀。保留每句台詞本文的字、標點、語言、空格與換行，外層引號、語言標籤、表演註記及排版所用的跳脫符號按來源格式辨識。遇到格式不明、口白身分不清或發話範圍難以切分，回原檔人工核實。
3. **逐句與逐請求核對。** 確認每個應發話的 ID 已出現、說話者相同、文字逐字一致、播放順序正確，並找到每句所屬鏡號及生成請求。反向檢查新增發話、同一 ID 的重說、放錯鏡頭或請求，以及無發話的請求是否夾帶新句。純分鏡核對至分鏡為止。可提交提示詞在送出前以將提交的正文重核一次。含發話鏡的請求另依[生成模式規則](mode-and-shot-rules.md#生成模式選擇)核對。
4. **核對跨鏡聲音。** 同一發話跨畫面時，一次登錄完整原句，在後續鏡的聲音欄標出延續及收尾，逐請求核對模型會在哪裡發出這句話。多個請求以剪輯承接一條對白音軌時，記明產生話音的請求與後製承接點，後續畫面沿用聲音時無須模型重念。該鏡依分鏡所定的聲音及[生成模式規則](mode-and-shot-rules.md#生成模式選擇)選擇模式。既有設計確實切為多段發話時，各片段沿用同一 ID，標出片段順序、鏡號和請求，依播放順序直接串接後須逐字還原原句。分鏡與請求都明載片段時，也要比對同一鏡號範圍實際分到的原文。實際重說、片段漏接或把切點移到其他字上，以及以「接續上一句」代替當次需產生的台詞，都列出發生位置。
5. **寫入結果與重審範圍。** 逐一列台詞 ID、差異、位置與處置。來源齊全且無差異才標該階段台詞對帳通過，有差異退回修正，缺證據標待核對。鎖定台詞需要更動時先取得核准並更新鎖稿；鎖稿、分鏡、正文、發話綁定或分組若有更動，重核受影響範圍。將結果附於製作品管證據及時長審核證據，沿用獨立盲審、語意、表演與時長審核。

## 製作旁表格式

表前登錄範圍、階段與各來源版本。位置用可回原檔的行號、欄位、欄位內序號、時間碼或段落。新增發話可用臨時 ID 並標出來源位置，漏句保留鎖稿 ID 及預期鏡號或請求。

| 場次／台詞 ID | 鎖稿位置／說話者／原句 | 分鏡位置與實際發話 | 請求版本／正文位置與實際發話 | 差異／處置 |
|---|---|---|---|---|
| `C01-D01` | `script.md @ v2` 第 8 行 ／ 阿寧 ／ 你先等我，別走。 | `S001` 旁白對白原句，`S002` 聲音欄標延續至尾 | `G001 @ v3` 1.5–4.0 秒，`(S1)` 對應阿寧，正文發話一次「你先等我，別走。」 | 跨兩鏡，一次發話 |

## 選用的機讀比對

將各階段已對照原檔的發話記錄成 UTF-8 JSON，按發話播放順序排列。可在套件外執行下列指令，並把輸入與結果一同留存於製作品管證據。

```sh
python skills/film-quality-control/scripts/check_locked_dialogue.py /absolute/path/dialogue-trace.json
```

下例為單次跨鏡發話。`scope` 填實際場次及鏡號範圍。每份 `source` 填檔案或可還原正文的快照與版本。`location` 填來源內的位置。每個請求的 `shot_ids` 列出該請求涵蓋鏡號，各筆台詞的 `shot_ids` 只列這次生成話音對應的鏡號，依播放順序排列。由同一請求產生且跨鏡的原句可列多個鏡號。另行錄製或僅於後製跨鏡承接的台詞，依實際生成範圍另列對照，並明示該部分以人工核對。

```json
{
  "scope": "第 1 場，S001–S002",
  "stage": "prompt",
  "script": {
    "source": "script.md @ v2",
    "lines": [
      {"id": "C01-D01", "speaker": "阿寧", "text": "你先等我，別走。", "location": "第 8 行"}
    ]
  },
  "storyboard": {
    "source": "board.md @ v4",
    "lines": [
      {"id": "C01-D01", "speaker": "阿寧", "text": "你先等我，別走。", "location": "S001 旁白對白、S002 聲音描述", "shot_ids": ["S001", "S002"]}
    ]
  },
  "requests": [
    {
      "id": "G001",
      "source": "G001.txt @ v3",
      "shot_ids": ["S001", "S002"],
      "lines": [
        {"id": "C01-D01", "speaker": "阿寧", "text": "你先等我，別走。", "location": "1.5–4.0 秒，(S1) 對應阿寧", "shot_ids": ["S001", "S002"]}
      ]
    }
  ]
}
```

- 純分鏡使用 `stage: "storyboard"`，省略 `requests` 或填 `[]`。可提交提示詞使用 `"prompt"`，實際提交快照使用 `"submission"`。後兩者列出本次核對的所有請求，無發話的請求填 `lines: []`。
- 真正分成多段的發話在分鏡或請求逐筆用同一 `id`，加上從 1 開始的 `fragment` 整數。這些片段須在該階段相鄰，照播放順序登錄。兩邊都明載片段時，檢查器也比對每組依序出現的鏡號所分到的文字，相鄰且在同一鏡內的片段可以合併後比對。若其中一邊只記整句及跨鏡延續，檢查器依整句文字與對應鏡號核對；實際換鏡落點由審核人員核實。若鎖稿有特殊搶話與交疊，人工對照完整播放順序並記錄證據。
- 退出碼 `0` 表示輸入紀錄一致，`1` 表示找到差異或輸入格式有誤；問題列在 JSON `issues`。範圍完整性、來源是否為實際正文、角色／聲線對照、片段是否確實會發音及成片是否實現設計，都由審核人員依原檔及實際可得證據確認。工具只讀這張結構化旁表。
