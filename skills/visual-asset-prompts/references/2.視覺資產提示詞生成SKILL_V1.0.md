**定位**：從劇本中提取角色、場景、道具等視覺資產，生成純美術資產文生圖提示詞。  
**接口目標**：為視頻提示詞生成 skill 提供統一的 `@資產名` 引用，但本 skill 不承擔視頻分鏡、空間調度、連續性約束或鏡頭執行說明。

## 最高優先級規則

1. 本 skill 只負責視覺資產文生圖提示詞，不生成視頻分鏡提示詞。
2. 在處理劇本前，必須先向用戶確認視覺風格；除非用戶已經明確給出風格。
3. 角色資產和場景資產文生圖提示詞固定使用 `21:9`；道具資產文生圖提示詞固定使用 `16:9`。
4. 資產庫只輸出 `@資產名`、資產類型、文生圖提示詞。
5. 默認不輸出短描述、連續性約束、空間結構、使用規則、視頻交接說明。
6. 角色提示詞只寫人物本體，最終文生圖提示詞使用“純白無縫背景，僅呈現角色本體、服裝與隨身飾品”等正向約束，不寫入場景、背景、職業道具、手邊物、車輛、鍋具、屏幕、蒸汽等外部對象。
7. 所有場景提示詞必須使用“無人空鏡場景，僅呈現空間結構、固定陳設和環境質感”等正向約束；自檢時確認沒有人物、人臉、路人或主體角色。
8. 門內人、電話聲、OS 聲音、回憶中未露面的對象，若劇本沒有可見形象，不得腦補正面人物視覺。
9. `參考風格基調` 只用於場景資產提示詞；角色資產和道具資產不得直接寫入“雨夜、港片雨夜、霓虹街景、冷暖街燈、老城區場景”等會汙染背景或環境的風格詞。
10. 不是所有資產都生成多狀態；必須由劇本中的可見變化、時間變化、物理變化、信息變化或明確回憶段落觸發。
11. 只有當狀態變化會改變靜態資產圖的視覺識別，並且後續鏡頭需要穩定複用時，才生成多狀態。
12. 多狀態資產必須保留同一資產的基礎一致性錨點，只改變劇本中明確發生變化的狀態變量。
13. 狀態變化隻影響視頻動作、表演節奏或鏡頭調度時，不生成新的資產狀態。
14. 單一角色默認 1-4 個狀態，單一場景默認 1-5 個狀態，單一道具默認 1-4 個狀態；超過上限時合併相近狀態。
15. 面向 GPT 圖片模型輸出時，最終文生圖提示詞優先使用正向目標，不大量使用“不要、禁止、無、非”等負向描述。
16. 最終文生圖提示詞避免使用會誘發過銳或堆料的詞，如“精細、複雜、繁複、濃郁、HDR、高細節、8K、超高清、銳利、ultra sharp、hyper-detailed、intricate”。
17. 電影膠片風格包只在用戶選擇“電影寫實、真人寫實、寫實電影感、現實主義影像”等寫實類風格時調用；3D、2D、日系、賽博朋克、插畫、動畫等非寫實類風格不默認調用。
18. 外部參考資料中的動作中段、鏡頭景別、雙人對手戲、人物在場景中做什麼等內容屬於視頻/分鏡提示詞，不進入本視覺資產庫。

## Step 0：視覺風格確認

當用戶要求“使用本 skill 處理劇本”且未明確給出風格時，必須先詢問用戶，不得直接生成資產庫。

詢問時必須先提醒：

```text
建議使用 GPT Image 2 生成本資產庫中的圖片提示詞；本 skill 已按 GPT 圖片模型的出圖習慣優化提示詞結構。
```

必須確認：

```text
1. 視覺風格：寫實電影感 / 賽博朋克 / 3D / 2D / 日系 / 其他
2. 參考風格基調：例如《隱秘的角落》冷現實主義 / 霓虹賽博老城區 / 港片雨夜 / 日式清冷生活流 / 其他
```

可選確認：

```text
1. 角色設定圖是否需要三視圖。
2. 場景圖是否需要空鏡版本。
3. 道具圖是否需要白底設定圖。
```

如果用戶回覆“按默認來”，使用：

```text
視覺風格：真人寫實電影感
參考風格基調：現實主義懸疑短片，低飽和冷暖對比
角色設定圖：右側為角色頭部高清特寫，左側為角色全身三視圖（正面/側面/背面）
場景圖：空鏡，無人物
道具圖：中性背景或白底高清設定圖
```

## 資產分類

### 1. 角色資產

適用對象：
- 主要角色。
- 有臺詞或關鍵表演的人物。
- 需要跨鏡頭保持外貌一致的人物。

角色提示詞只允許包含：
1. 年齡、身份、職業氣質、地域氣質。
2. 臉型、骨相、五官結構。
3. 1-2 個核心視覺記憶點。
4. 眼睛、眉毛、鼻子、嘴唇、髮型。
5. 皮膚質感、生活痕跡。
6. 服裝、飾品。
7. 情緒氣質，但不寫誇張表演。

角色提示詞禁止包含：
- 場景、背景、街道、店鋪、房間、樓道。
- 職業道具、手邊物、車輛、外賣箱、鍋具、屏幕、傘、手電。
- 光源環境、蒸汽、雨景、門縫、桌椅等外部對象。
- “雨夜、港片雨夜、霓虹街景、街燈、老城區街道”等場景氛圍詞。
- 具體鏡頭、機位、運鏡、動作段。

### 2. 場景資產

適用對象：
- 故事發生的主要空間。
- 跨鏡頭重複出現的位置。
- 與美術風格、空間氣氛有關的場景局部。

場景提示詞必須包含：
1. 時間、天氣、地點。
2. 空間結構和可見動線。
3. 光源位置和色溫。
4. 場景中的固定物和關鍵陳設。
5. 場景質感、年代感、生活痕跡。
6. 固定視覺符號。
7. 使用正向約束表達為無人空鏡場景，僅呈現空間結構、固定陳設和環境質感；自檢確認沒有人物、人臉、路人或主體角色。

### 3. 道具資產

適用對象：
- 劇情關鍵道具。
- 角色反覆觸碰或觀看的物件。
- 需要近景保持一致的物件。

道具提示詞必須包含：
1. 尺寸和比例參照。
2. 材質、磨損、使用痕跡。
3. 劇情識別點。
4. 中性背景或白底設定圖。

道具提示詞禁止包含：
- 角色正在使用道具的動作。
- 完整場景、複雜背景、多人互動。
- “雨夜、港片雨夜、霓虹街景、街燈、老城區街道”等場景氛圍詞，除非道具本身必須表現雨水、泥點、磨損等物理痕跡。
- 視頻鏡頭、機位、運鏡。

## 資產多狀態判斷規則

### 1. 多狀態總原則

先判斷資產是否必須資產化，再判斷是否需要狀態化。多狀態不是擴寫裝飾，而是為了解決同一角色、場景、道具在劇本中出現明顯靜態視覺差異時的穩定複用問題。

必須生成多狀態的情況：
- 同一資產在劇本中出現明顯可見差異。
- 該差異會影響文生圖結果的外觀識別。
- 該差異後續可能被視頻提示詞多次引用。

不生成多狀態的情況：
- 只是角色動作、表情瞬間、站位、坐姿、轉身、奔跑。
- 只是鏡頭遠近、機位、運鏡、剪輯節奏。
- 只是短暫情緒變化，且不改變服裝、妝髮、傷痕、年齡、體態等靜態外觀。
- 只是場景中一次性光影變化，且不影響場景固定美術設定。

視覺差異不足的狀態必須合併，例如“疲憊、失眠、虛弱、崩潰”如果外觀差別不大，可合併為一個 `@角色名_疲憊` 狀態。

### 2. 角色多狀態觸發

角色出現以下變化時，才生成多狀態：
- 年齡階段變化，如幼年、成年、老年。
- 換裝或身份偽裝，如校服、婚服、制服、偽裝身份。
- 受傷、病態、血汙、燒傷、明顯疲憊等靜態外觀變化。
- 髮型、妝容、體態、整潔程度發生明顯變化。
- 現實與回憶中的人物形象不同。
- 時間跨度造成外貌變化。

角色多狀態必須保留：
- 臉型、骨相、眉眼、鼻嘴結構、核心髮型特徵。
- 1-2 個核心視覺記憶點。
- 基礎身份氣質。

角色多狀態只能改變：
- 年齡、服裝、傷痕、汙損、妝髮、體態、整潔程度、長期情緒氣質。

角色狀態名可以來自劇情，但提示詞不得寫入場景。例如 `@艾莉_受傷` 可以寫溼發、衣物汙損、臉部擦傷，不得寫雨夜街道、門口、車輛、燈光環境。

### 3. 場景多狀態觸發

同一場景出現以下變化時，才生成多狀態：
- 白天、夜晚、黃昏、深夜等時間造成明顯美術差異。
- 正常、破敗、災後、焚燬、廢棄等物理狀態變化。
- 現實、回憶、夢境等段落造成明確視覺狀態變化。
- 整潔、凌亂、被搜查、被破壞、長期無人等陳設狀態變化。
- 天氣或光源變化成為該場景的關鍵視覺識別點。

場景多狀態必須保留：
- 空間結構、可見動線、固定陳設、材質年代感、核心視覺符號。

場景多狀態只能改變：
- 時間、天氣、光源、損壞程度、陳設狀態、清潔程度、色溫、氣氛。

場景資產可以寫“正面全景設定圖、俯視結構設定圖、空鏡設定圖”等構圖視角，但不得寫具體鏡頭運動、分鏡執行或攝影機調度。

### 4. 道具多狀態觸發

道具出現以下變化時，才生成多狀態：
- 完整、破損、沾血、燒燬、泥汙、老化等物理狀態變化。
- 合上、打開、半開、拆開、封存等開合狀態變化。
- 空白頁、關鍵頁、署名頁、報警界面、裂痕照片等信息狀態變化。
- 被包裹、露出一角、完整顯露等隱藏狀態變化。
- 劇情關鍵標記、裂痕、編號、文字、貼紙、汙漬發生變化。

道具多狀態必須保留：
- 尺寸比例、材質、形狀、顏色、基礎磨損、核心識別符號。

道具多狀態只能改變：
- 開合、損壞、汙染、文字內容、顯露程度、關鍵標記。

道具狀態不得寫人物手持動作、使用過程、完整場景或視頻鏡頭。

### 5. 狀態命名規則

多狀態資產命名使用：

```text
@資產名_狀態詞
```

規則：
- `@資產名` 是資產組名，默認不單獨作為生成圖提示詞。
- `@資產名_狀態詞` 是可生成、可引用的具體狀態資產。
- 狀態詞 2-6 個漢字優先，避免過長。
- 狀態詞只寫視覺狀態，不寫完整句子。

推薦：

```text
@艾莉_成年
@艾莉_幼年
@艾莉_受傷
@溫室倉_正常
@溫室倉_破敗
@溫室倉_回憶
@日記本_合上
@日記本_關鍵頁
@日記本_燒燬
```

禁止：

```text
@艾莉_雨夜街頭崩潰大哭
@溫室倉_深夜紅燈故障破敗狀態
@日記本_被男主拿在手裡翻到關鍵頁
```

## GPT 圖片模型適配規則

### 1. 正向約束優先

GPT 圖片模型對負向提示詞不穩定，寫“不要 X”可能反而激活 X。因此最終文生圖提示詞優先寫成正向目標：

```text
純白無縫背景，僅呈現角色本體、服裝與隨身飾品
無人空鏡場景，僅呈現空間結構、固定陳設和環境質感
白底或中性背景，僅呈現單一道具
```

內部規則和自檢可以繼續判斷“不能出現什麼”，但最終輸出給模型的提示詞應儘量少寫“禁止出現、不要、無、非”等負向句式。

### 2. 避免過銳和堆料

最終文生圖提示詞避免使用：

```text
精細、複雜、繁複、濃郁、HDR、高細節、8K、超高清、銳利、ultra sharp、hyper-detailed、intricate、HDR photography
```

推薦替換為：

```text
清晰且邊緣柔和，柔和邊緣過渡，剋制細節，大色塊優先，材質語言統一，乾淨通透，膠片柔光，必要結構細節保留
```

### 3. 三類資產 GPT 質感尾綴

角色資產可吸收：

```text
真實皮膚質感，自然膚色不均，毛孔剋制可見但不堆砌，頭髮有真實重量感和自然分股，眼睛有溼潤真實反光，柔焦邊緣，膠片柔光，剋制細節。
```

場景資產可吸收：

```text
柔和邊緣過渡，剋制細節，大色塊優先，材質語言統一，空間層級清楚，單一視覺焦點，電影級柔光，畫面乾淨通透。
```

道具資產可吸收：

```text
材質統一干淨，邊緣柔和但形體清楚，保留必要結構細節，弱化碎紋理，白底或中性背景設定圖。
```

### 4. 電影寫實風格包調用條件

當用戶選擇或明確暗示以下風格時，可調用電影寫實風格包：

```text
電影寫實、真人寫實、寫實電影感、現實主義影像、膠片電影感、短片寫實風格
```

可選風格包：

```text
膠片電影美術設定圖質感，柔和對比度，黑位略微提亮，自然光與實用光源主導，高光自然暈染，淺景深柔光，自然膠片顆粒，呈現電影劇照般的剋制影調、真實材質和柔和層次。
```

當用戶選擇以下風格時，不默認調用電影寫實風格包：

```text
3D、2D、日系、賽博朋克、插畫、動畫、國漫、美漫、像素、黏土、定格動畫、低多邊形
```

這些非寫實風格只保留“正向約束、剋制細節、統一材質、避免過銳”的 GPT 通用規則，不套用具體電影、攝影師、膠片品牌或攝影規格等寫實電影詞。

### 5. 不吸收的內容

以下內容不進入視覺資產庫：
- 捕捉於動作中段、動態模糊、人物在場景中做什麼。
- 特寫鏡頭、中景、全景、雙人對手戲等鏡頭模板。
- 鏡頭景別、機位、運鏡、剪輯節奏。
- 圖生圖重繪、二次精修模型、模型串聯工作流。

以上內容可轉交視頻提示詞 skill 或分鏡圖工作流使用。

## `@資產名` 命名規則

### 推薦命名

```text
@小美
@咖啡廳靠窗位
@日記本
@舊手機
@便利店收銀臺
```

### 禁止命名

```text
@一個穿淺色風衣的疲憊年輕女人
@下著雨的咖啡廳靠窗的位置
@那個很舊的深棕色日記本
```

規則：
- `@資產名` 不超過 8 個漢字為佳，複雜空間不超過 12 個漢字。
- 資產名只表達身份，不塞完整描述。
- 同一資產全文件保持同名。
- 場景局部可以獨立資產化，如 `@咖啡廳靠窗位`、`@便利店收銀臺`。
- 不重要的一次性物件不用 `@`。

## 輸出流程

### Step 1：提取視覺資產

內部建立三類清單，默認不輸出完整分析表：

```markdown
| 類型 | 原文名稱 | 建議資產名 | 是否必須資產化 | 是否需要多狀態 | 狀態依據 | 建議狀態 |
|:---|:---|:---|:---:|:---:|:---|:---|
```

判斷標準：
- 跨鏡頭出現：必須資產化。
- 影響劇情：必須資產化。
- 影響美術風格：必須資產化。
- 只是背景裝飾：可不資產化。
- 有劇本證據且靜態視覺識別明顯變化：需要多狀態。
- 只有動作、表情、機位或剪輯變化：不需要多狀態。

### Step 2：生成純資產文生圖提示詞

每個資產只輸出：
- `### @資產名`
- `類型：角色 / 場景 / 道具 / 不可見聲音角色`
