# 劇本框架

本次對話首次使用時，由主代理依 [版本檢查](../screenplay-director/references/skill-update-check.md) 核對一次。單獨安裝時，以實際安裝的 Git 提交或 `.ai-film-skills-revision` 比對 [上游 main](https://github.com/shoung/ai-film-skills/commits/main/)。有新版先確認是否更新，無法驗證則簡述後繼續。

## 全新劇本的入口

開發全新劇本時，依 [共用啟動訪談](../screenplay-director/references/startup-intake.md) 沿用已知綱要及授權。單獨安裝時先讀已有資料，把可獨立回答的重大缺項列同一輪，首輪通常 2–4 題，每題附建議與理由。若只有一個前提可先決定，先問一題。等回覆後再問依賴前輪答案的問題。方向摘要確認後，依委託開始方向卡、角色設定或大綱。已有核准綱要或明確委託代決時直接接續。缺共用識別資產時，新創作只在對話中顯示一次 `SHOUNG`，續作、維護或一般交接不重複，標記留在交付物外。

以原著改編立項時，若核准綱要與來源分析皆缺，使用 [原著分析](../screenplay-source-analysis/SKILL.md) 分析指定範圍。單獨安裝時從可取得的原文記下必留內容、因果與知情進度，附章節及位置。缺來源時明列待核，維持候選狀態，待作者確認再形成正式設定。

方向卡、設定、大綱、專案檔案與對標分析依 [antigravity-writer](../antigravity-writer/SKILL.md) 分流。單獨安裝時用 [寫作備援](references/writer-fallback.md)。

## 執行方式

依本次委託選讀 [方向、對標與大綱](references/development.md) 的相關段落。整理設定或交接時用 [專案檔案模板](references/project-file.md)，沿用專案既有格式與鎖定決策。原著改編依來源和核准的改編底線整合候選，定稿記下必留事件、證據位置和知情進度。

編排連載分集大綱或核定分集前，依 [連載分集規劃與驗收](references/serial-episode-planning.md) 核對每集局部兌現、前後集承接、鉤子與兌現紀錄。改編須逐項標示必留事件、來源位置及揭露進度，隨核定大綱交給寫作與會診。未定的候選和缺少正文的相鄰集保留其查核狀態。

核准的大綱與專案檔交給 [劇本寫作](../screenplay-writing/SKILL.md)，未解的結構問題按委託交 [劇本醫生](../screenplay-doctor/SKILL.md)。交接附版本、鎖定內容、確認或授權、來源和待決事項。以繁體中文工作，接受繁簡同義指令。
